## 📌 프로젝트 소개

이 프로젝트는 **콘솔 환경에서 장기를 둘 수 있는 간단한 애플리케이션**을 구현한 토이 프로젝트입니다.

장기의 기본적인 룰을 이해하고 있고 개인적으로 좋아하는 게임이기 때문에,  
**기본 규칙을 충실히 반영한 장기 게임을 직접 구현해보고자** 프로젝트를 시작했습니다.

프로젝트를 통해 단순 기능 구현보다는,  
최근에 학습했던 **읽기 좋은 코드 작성 사고법**과 **실용적인 테스트 가이드**를  
실제 코드에 적용해보는 것을 주요 목표로 삼았습니다.

---

## 🎯 프로젝트 목표

- 장기 기본 룰을 코드로 명확하게 표현
- 테스트 기반으로 안정적인 설계 및 리팩토링 수행
- 객체지향적인 구조를 통해 확장 가능한 설계 경험

특히 아래 항목들을 중점적으로 고려하며 개발했습니다.

1. **엣지 케이스(모서리/예외 상황)까지 커버하는 테스트 작성**
2. **직관적인 메소드/클래스 명명**을 통해 코드 의도가 명확히 드러나도록 설계
3. 필요 시 **일급 컬렉션을 적극 활용**하여 책임과 역할을 분리

---

## 기능

1. 게임 시작
    - [x] 보드 생성
        1. [X] 각 팀의 포메이션 선택
        2. [X] 초나라/한나라로 고정/유동 기물 생성
        3. [X] 초나라 턴으로 지정

2. 게임 진행 (반복)
    1. [X] 보드 기물 출력
    2. [X] 기물 선택
        1. [X] 위치 Input 받기 예 ) A1
        2. [X] 기물 검증
            - [X] 해당 위치가 보드 범위에 있는지
            - [X] 해당 위치에 기물이 있는지
            - [X] 해당 기물이 현재 턴인 팀 기물인지
            - [X] 해당 기물이 이동 가능한 위치가 한 개 이상인지
    3. [X] 기물 이동
        1.[X] 기물 이동 위치 Input 받기 예 ) B2
        2.[X] 이동 위치 검증
            - [X] 해당 위치가 보드 범위에 있는지
            - [X] 해당 위치가 현재 기물이 이동 가능한 위치인지
            - [X] 해당 위치에 기물이 있을 경우 적 팀 기물인지
            - [X] 해당 위치에 적 팀 기물이 있다면 제거 후 자리 차지
    4. [X] 턴 변경
    5. [X] 게임 종료 조건 확인
        - [X] 왕이 죽으면 패배

## 🛠️ 주요 구현 내용

- 콘솔 기반 장기 게임 플레이
    - 보드 생성 및 초기 기물 배치
    - 턴 기반 입력 및 진행
    - 기물 이동 가능 여부 검증
    - 게임 종료 조건 처리
- 각 기물의 이동 규칙을 개별 객체로 분리하여 구현
- `Direction`, `Movement`, `Movements` 구조를 통한 이동 로직 추상화
- 테스트 기반 설계를 통해 **기본 util/io를 제외한 모든 클래스에 대해 테스트 커버리지 100% 달성**

## 🧠 진행하며 얻은 인사이트

### 📌 문서화의 중요성

기능 구현을 진행하다 보니,  
중간중간 특정 규칙을 구현하는 과정에서 **처음 의도했던 설계 포인트를 놓치는 경우**가 발생했습니다.

이를 해결하기 위해 `README.md` 등 문서를 통해
- 현재 구현 상태
- 고려 중인 규칙
- 논리적 흐름이 처음 설계와 맞는지

를 지속적으로 점검하며 진행했고,  
이 과정을 통해 **문서화가 단순 정리가 아니라 설계를 지켜주는 도구**라는 점을 체감했습니다.

---

### 📌 테스트가 리팩토링의 안전장치가 되다

차 / 포 기물의 이동 로직을 구현하면서  
단순한 방향 나열만으로는 한계를 느껴 `Direction` enum과 이를 감싸는 `Movement` 일급 컬렉션을 도입했습니다.

이후 구현을 확장하다 보니 `Movement`들을 다시 묶는  
`Movements`라는 상위 일급 컬렉션이 필요하다고 판단했지만,  
구조 변경에 대한 부담이 있었습니다.

하지만 테스트를 꼼꼼히 작성해 둔 덕분에  
**기존 동작에 대한 신뢰를 바탕으로 과감한 리팩토링을 진행**할 수 있었고,  
차의 대각선 이동 규칙 추가 역시 기존 로직에 영향을 주지 않고 확장할 수 있었습니다.

**리팩토링 시 안정성을 확보하는 것을 목표**로 했습니다.
